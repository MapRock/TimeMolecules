Prompt: How can an AI agent understand the TimeSolution database schemas well enough to find the right tables, follow the data flow, and write correct queries?

Abstract: TimeSolution organizes database objects into purpose-specific SQL Server schemas so an AI agent can reason about the system from a cold start. The APP schema holds custom extension tables, ETL holds upstream loading structures, STAGE receives landing data such as STAGE.ImportEvents, and the core TimeSolution model flows into FACT and DIM schemas for star or snowflake dimensional analysis. DV provides a Data Vault-style layer, KPI contains performance-management definitions, and WORK serves as a temporary hand-off interface between modular processing steps, especially for MPP-friendly designs. An agent should use these schema roles to decide where to search for raw events, derived facts, dimensions, KPI drivers, temporary transition tables, and downstream semantic structures. The material also includes a SQL Server query against sys.schemas and sys.extended_properties to retrieve current schema descriptions dynamically, ensuring agent behavior stays aligned with the database itself.
